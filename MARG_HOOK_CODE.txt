================================================================================
MARG ERP -> WhatsApp : hook setup
================================================================================

Flow
  FOOTER END  reads the party mobile, asks Y/N, runs trigger_bill.bat
  HEADER END  optional safety net for the mobile
  Python      picks up bill_hook.txt and sends the PDF on WhatsApp

Paste in Marg: Masters -> Marg Setups -> Advance Features -> Self Programming
Then: Development Hook for HEADER END / FOOTER END -> Commands
Save each with Ctrl+W -> Save -> Exit

STEP 1 — FOOTER END   (required — this one does everything)
================================================================================

myv_bill=trim(invo)
myv_code=trim(pcod)
myv_name=trim(chemi_name)
myv_amt=ltrim(str(finalbilval))
myv_date=trim(repdat1)

myv_phone=""
IF TYPE("marg_wa_phone")="C"
  myv_phone=ALLTRIM(marg_wa_phone)
ENDIF
IF LEN(ALLTRIM(myv_phone))<10 AND USED("ORDER")
  myv_flds="PHONE4,PHONE3,PHONE2,PHONE1"
  FOR ln_p=1 TO GETWORDCOUNT(myv_flds,",")
    myv_try=CHRTRAN(ALLTRIM(TRANSFORM(EVALUATE("ORDER."+GETWORDNUM(myv_flds,ln_p,",")))),"+- ()./,","")
    IF LEN(myv_try)>=10
      myv_try=RIGHT(myv_try,10)
      IF LEFT(myv_try,1)$"6789"
        myv_phone=myv_try
        EXIT
      ENDIF
    ENDIF
  ENDFOR
ENDIF

marg_wa_send="N"
DEFINE WINDOW wa_popup FROM 8,8 TO 19,72 TITLE "  WhatsApp - Send Invoice  " DOUBLE SHADOW
ACTIVATE WINDOW wa_popup
@ 1,3 SAY "Bill No   : "+ALLTRIM(myv_bill)
@ 2,3 SAY "Party     : "+LEFT(ALLTRIM(myv_name),38)
@ 3,3 SAY "Amount    : Rs "+ALLTRIM(myv_amt)
@ 4,3 SAY "Date      : "+ALLTRIM(myv_date)
IF LEN(ALLTRIM(myv_phone))>=10
  @ 5,3 SAY "Mobile    : "+ALLTRIM(myv_phone)
ELSE
  @ 5,3 SAY "Mobile    : NOT FOUND - add mobile in ledger master"
ENDIF
@ 7,3 SAY REPLICATE("-",54)
@ 8,3 SAY "Send this bill to customer on WhatsApp?"
@ 9,3 SAY "  [ Y ]  Yes, send now          [ N ]  No, skip"
@ 10,3 SAY "Type Y or N and press Enter :"
@ 10,33 GET marg_wa_send PICT "!" VALID UPPER(marg_wa_send)$"YN"
READ
DEACTIVATE WINDOW wa_popup
RELEASE WINDOW wa_popup

IF UPPER(ALLTRIM(marg_wa_send))="Y"
  marg_wa_send="Y"
ELSE
  marg_wa_send="N"
ENDIF
marg_whatsapp_line=trim(myv_bill)+"|"+trim(myv_code)+"|"+trim(myv_name)+"|"+trim(myv_amt)+"|"+trim(myv_phone)+"|"+trim(myv_date)+"|"+marg_wa_send
=strtofile(marg_whatsapp_line,"D:/MARGERP/HOOK_DATA/bill_hook.txt")
run /n d:/marg-whatsapp-automation/trigger_bill.bat
retu .t.

Output line: bill|code|name|amount|phone|date|sendYN

Marg keeps the ORDER table positioned on the party you selected, so its current
record already IS the right party. The lookup is read-only — no SELECT, no
LOCATE, no pointer move — so Marg's own save logic is untouched.

================================================================================
STEP 2 — HEADER END   (optional safety net)
================================================================================
Only needed if Marg ever moves the ORDER pointer before FOOTER runs. It grabs
the mobile earlier and parks it in a PUBLIC variable the FOOTER checks first.

PUBLIC marg_wa_phone
marg_wa_phone=""
IF USED("ORDER")
  myv_flds="PHONE4,PHONE3,PHONE2,PHONE1"
  FOR ln_p=1 TO GETWORDCOUNT(myv_flds,",")
    myv_try=CHRTRAN(ALLTRIM(TRANSFORM(EVALUATE("ORDER."+GETWORDNUM(myv_flds,ln_p,",")))),"+- ()./,","")
    IF LEN(myv_try)>=10
      myv_try=RIGHT(myv_try,10)
      IF LEFT(myv_try,1)$"6789"
        marg_wa_phone=myv_try
        EXIT
      ENDIF
    ENDIF
  ENDFOR
ENDIF
retu .t.

Nothing is written to disk here: the mobile travels to FOOTER END in the PUBLIC
variable. If the popup in STEP 1 still shows a mobile without this hook
installed, you do not need it — STEP 1 covers the lookup on its own.

================================================================================
STEP 3 — Leave Marg's own WhatsApp bill message ON
================================================================================
Masters -> Marg Setups -> Control Room -> SMS/WhatsApp Setup

Marg renders the real invoice PDF only as part of this flow, so turning it off
removes the very file we send. Enable the message on bills and set the PDF copy
to apply to all parties.

Marg queues the PDF and a CSV into D:/MARGERP/emailserver and never delivers
anything itself, so the customer is not messaged twice.

Marg runs this flow on bill DELETE as well. Answer No to that prompt — our hook
does not fire on delete, so nothing is sent either way.

================================================================================
CONFIRMED FIELD MAP (this installation)
================================================================================
Bill no       INVO             e.g. INV0453
Party code    PCOD             e.g. WAD     <- bill alias code
Party name    CHEMI_NAME       party name as printed on the bill
G Total       FINALBILVAL
Date          REPDAT1
Party master  alias ORDER      D:/MARGERP/DATA/ORDER.A20, ~1900 records
  SCODE       internal code    e.g. C6      <- NOT the same as PCOD
  PARNAM      party name, space-padded ("NAME     CITY")
  PHONE4      10-digit mobile               <- PHONE1..3 empty in our data

Because PCOD (WAD) != SCODE (C6) and PARNAM is padded, LOCATE on either one
fails. That is why the hooks read ORDER's CURRENT record instead of searching.

Never use: invopho (always blank here), order.mobile / order.mob (no such
field), MEMOREAD() (missing from Marg's runtime - use FILETOSTR), sndlast_5
(does not exist at FOOTER), vou_position, an.

================================================================================
BILL PDF — send Marg's real invoice
================================================================================
Saving a bill makes Marg queue its own GST invoice (items, batches, HSN, GST
breakup, QR) as

  D:/MARGERP/emailserver/invoice(N).pdf

beside a CSV named after the bill, e.g. <company>_<date>_s_inv0453(N).csv. That
sidecar names the bill outright, so the right PDF is identified without reading
a page of it and without any keystrokes.

Three traps that shaped the matching logic:
  - Marg reuses the copy number N instead of counting upwards, so a PDF can be
    rewritten for another bill while an older CSV still claims that number.
    Only files written together count as a pair.
  - The hook fires BEFORE Marg finishes writing, so a PDF is ignored until its
    %%EOF trailer is on disk. Taking it early fails on a Windows file lock.
  - Marg's print-screen Export writes a fixed
    C:/Users/Public/MARG/<company>/AA/invoice.pdf and overwrites it every time,
    so that name proves nothing. It is accepted only when written after the
    save AND the bill number is found in its text (needs pypdf).

Each accepted PDF is copied to EXPORT/BILLS/<bill>.pdf before the next one
overwrites it. Our own generated invoices go to EXPORT/BILLS/fallback/ and are
marked, so they are never mistaken for Marg's.

Troubleshooting

                               in a field other than PHONE1..PHONE4
  "WhatsApp server offline" -> START_SERVER.bat is not running
  "<NAME>.PRG does not exist" -> that function is missing from Marg's runtime;
                               FoxPro treats unknown names as program calls
